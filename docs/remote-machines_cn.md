# 远程受控机器 (Remote machines) — 在另一台计算机上运行 OpenWorker

[English](remote-machines.md) · [简体中文](remote-machines_cn.md)

你可以在远程虚拟机、家庭服务器或闲置备用机上运行 OpenWorker Agent，并通过桌面端客户端进行远程控制。会话持久驻留在远程机器上，**即使你的笔记本电脑合上盖子或离线，后台任务仍然持续运行**——当你重新连接时，可以无缝接续工作状态。

在开始任何配置之前，有几项核心架构设计原则需要了解：

- **远程机器主动向你反向拨号连接（Dial out）**：接入的受控机器不会对外监听任何端口，也不接受入站网络连接——它只会建立一条指向你的桌面端应用的单向出站长连接并持续保持。远程机器上无需对外暴露端口、无需配置防火墙端口映射，也无需做复杂的暴露面加固。
- **数据保留在远程机器本地**：会话在远程机器本地磁盘上运行和持久化。桌面端仅在连接状态下进行实时查看，并在断开连接后保存一份你已查阅内容的只读副本供离线翻阅。
- **每台机器独立管理自己的密钥**：你部署的模型 API Key 和连接器密钥会被复制到远程机器本地的密钥存储中，且使用该机器的公钥进行端到端加密传输——配置完成后，机器可完全脱离控制端独立运行模型调用。

## 环境要求 (What you need)

- 运行在你的 Mac 或 Windows PC 上的 OpenWorker **桌面端应用**（充当 Controller 控制端）。
- 一台具备 Python 3.10+ 环境的 **Linux 机器**（Ubuntu 22.04+ 或类似发行版，x64 或 ARM 架构均可）。
- 一条从远程机器**单向连通到**你的桌面端的网络路径——详见下文[网络连通性 (Reachability)](#网络连通性-reachability如何让机器找到你的桌面端)。Tailscale 是最简单的方案；若机器已有 SSH 访问权限，使用标准 OpenSSH 反向隧道即可直接连通。

## 1. 在远程机器上安装

在远程机器的终端中执行：

```bash
sudo apt update && sudo apt install -y git curl python3-venv python3-pip
python3 -m venv ~/ow-venv
~/ow-venv/bin/pip install "git+https://github.com/andrewyng/openworker.git"
```

可选但强烈推荐将 `openworker` 加入 PATH 环境变量：

```bash
echo 'export PATH=$HOME/ow-venv/bin:$PATH' >> ~/.bashrc && source ~/.bashrc
```

检查安装状态：

```bash
openworker machine status
```

你应该能看到 `controller: not joined`——表示这是一台尚未注册的新机器。

## 网络连通性 (Reachability)：如何让机器找到你的桌面端

远程机器需要连接到你桌面端应用运行的本地服务端（默认端口 8765）。由于桌面端默认仅监听 localhost，请选择以下两种连通方案之一：

**方案 A — Tailscale（推荐）**：在两台电脑上均安装 [Tailscale](https://tailscale.com)。在桌面端应用中，开启监听 Tailnet 网络接口，并在接入连接 URL 中使用桌面端的 Tailscale IP 地址。该方案在两端电脑重启后无需任何额外操作即可自动恢复连接。

**方案 B — SSH 反向隧道（无需安装任何新软件）**：如果你能从本地桌面端 SSH 登录到远程机器，只需在**你的本地桌面终端**执行以下命令并保持运行：

```bash
ssh -N -o ServerAliveInterval=15 -R 8765:localhost:8765 you@your-machine
```

该命令会将桌面端的 8765 端口映射到远程机器**本地的** `localhost:8765`——桌面端弹出的接入命令开箱即用，无需修改 IP。
注意：若任一端电脑重启，该 SSH 隧道会断开；建议使用 `autossh` 或系统进程守护工具保持隧道常驻。

## 2. 注册并接入机器 (Enroll the machine)

1. 在桌面端应用中：点击 **Settings → Machines → “Add a machine…”**。打开该卡片会*激活*接入流程：生成一个有效期为 10 分钟的一次性 Join Token。
2. 如果你希望机器在接入的一瞬间自动获得你当前配置的模型 API Key，保持勾选 **“Provision with my model keys”**（传输前会使用机器专属公钥加密；详见[密钥分发](#3-分发模型与工具密钥)）。
3. 复制卡片上展示的单行命令，并在远程机器终端上执行：

```bash
openworker join http://127.0.0.1:8765/j/<token> --name=my-box
```

卡片状态会即刻翻转为 **“✓ my-box joined”**，并显示该机器的公钥指纹 (Key Fingerprint)。在远程机器上运行 `openworker machine status` 确认指纹一致——该指纹即为该机器的唯一永久数字身份标识。此时该一次性 Token 已经作废销毁；后续的断线重连全部使用机器本地生成并在注册阶段绑定的非对称密钥对进行挑战签名认证，无需重复注册。

## 3. 分发模型与工具密钥 (Give the machine keys)

远程机器需要拥有自己的模型 API Key 才能执行 Turn 循环（它拥有独立的密钥、直接发起模型调用——运行时桌面端不参与转发流量）。提供密钥的三种方式：

- **注册接入时一键下发**：在添加机器卡片上勾选“Provision with my model keys”。
- **随时从桌面端下发**：机器注册成功后，**Settings → Models** 中的每个模型提供商卡片（以及基于 Key 的连接器卡片）都会多出一行 **“Available on”**——点击对应机器标签即可下发或撤销该 Key。后续若你在桌面端轮转（Rotate）了 Key，标签上会出现 ↻ 图标，点击即可同步更新。
- **直接在远程机器上配置**（适合对密钥出境有严格合规要求的场景）：

```bash
openworker machine keys set provider:openai api_key=sk-...
```

（或者通过环境变量/云厂商 Secret Manager 注入——机器端的配置库原生支持 `${VAR}` 占位符解析。）

从桌面端下发的密钥在离开你的桌面之前，都会使用目标机器的公钥进行加封密封（Sealed）；全网只有那台机器的私钥能够解密。注意：基于 OAuth 网页授权的账号（Google、Slack 等）**不会**在机器间同步——每台机器需各自独立完成第三方授权。

## 4. 使用远程机器

- **在远程机器上启动会话**：在输入框下方的配置栏中，当有已注册机器在线时，会出现 **runs on** 选项——选中 ⌂ my-box。模型选择器将自动切换展示该机器可用的模型。
- **基于工作目录的协作角色（代码编写、技术负责人）**：点击发送后，系统会询问在远程机器的哪个目录下展开工作——你可以输入一个路径（远程机器会自动校验路径有效性）、从最近使用的目录列表中点选，或者直接在机器上自动创建的临时工作目录中开始。
- **侧边栏标识**：远程会话会带有低调的 ⌂ 徽标；在“RECENT”列表的筛选分组菜单中，支持按 **Machine** 进行维度分组。
- **集中收件箱 (Inbox)**：任何已连接机器上的会话所触发的审批请求（Approval）与人机提问（Question），都会集中展示在你的桌面端收件箱中，并标明来源机器——你坐在办公椅上即可统一审批。
- **机器离线处理机制**：当机器离线时，其会话在列表中保持可见（置灰显示）。你此前已经打开过的会话记录依然可以完整阅读（处于只读模式并带有离线横幅提示）；新消息和新审批将原地等待机器恢复上线。远程服务在网络恢复后会自动重连。

## 5. 将其配置为系统常驻服务 (Run it as a service)

为了确保机器在用户登出或系统重启后依然持续提供服务，在远程机器上运行：

```bash
openworker machine service install
```

这会自动生成并启用一个 systemd 用户级服务单元，运行 `openworker up`（支持崩溃自动重启，5 秒指数退避）。若要在没有任何用户登录到终端的情况下依然保持服务运行，执行：

```bash
sudo loginctl enable-linger $USER
```

如需移除服务，运行 `openworker machine service uninstall`。（注意：若使用 SSH 隧道方案，桌面端的隧道脚本同样需要做常驻守护，如使用 `autossh` 或 LaunchAgent，否则远程机器将无法找到本地端口。）

## 5 行总结安全模型

- 远程机器**仅主动向外建立长连接**，自身不对外监听任何网络端口。
- 首次握手接入由你数秒前在桌面端生成的**单次有效 Token** 进行授权；后续每一次重连均基于远程机器私钥签名的挑战认证。
- 控制端 Controller 在初次注册时**固定绑定（Pin）**机器的公钥，任何声称拥有相同身份的二次并发连接请求均会被坚决拒绝。
- 下发的敏感密钥在离开桌面端之前均经过机器专属公钥的**端到端非对称加密**。
- 会话全部内容存放在远程机器本地磁盘；桌面端仅缓存你实际浏览过的内容，且仅用于离线查阅。

另外需要特别说明的是：登录 OpenWorker Cloud 账号绝不会篡改或上传当前电脑中的本地数据。你的会话、密钥与接入机器属于当前本地用户账号体系；Cloud 登录仅是在其之上提供额外的云端扩展机器与增值服务，登出时仅会隐藏云端资源。

## 常见问题排查 (Troubleshooting)

| 现象 | 可能原因 |
|---|---|
| `join` 命令报错 `not-enrolled` | Token 已超时失效（10 分钟有效期）或已被使用过——重新打开桌面端的添加机器卡片生成新链接。 |
| `join` 命令报错 `already-connected` | 另一进程占用了该机器身份（例如直接拷贝了 state 目录，或者后台服务已在运行）。一个身份只允许一个活跃连接。 |
| `join` 命令报错 `protocol-mismatch` | 桌面端与远程机器安装的版本差异过大——请升级版本较低的一方。 |
| 机器重启后在桌面端显示离线 | 服务端在开机数秒内会自动重连——如果未恢复，通常是桌面端的 SSH 反向隧道随之挂掉了。 |
| 执行 Turn 报错缺少 API Key | 远程机器在调用模型时使用的是**它本地的**密钥——请下发密钥（见第 3 节）或在会话模型选择器中检查机器可用模型。 |

远程机器上的运行状态保存在 `~/.config/coworker`（包含身份密钥对、加密密钥库和会话数据）。执行 `openworker machine leave` 会彻底抹除注册记录**以及**机器身份——后续重新接入需要重新生成 Join URL，并且旧机器记录可直接在桌面端 Machines 设置页中删除。
